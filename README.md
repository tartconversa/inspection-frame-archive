# 工业视觉归档的图像译码与可追溯读片

工业相机的初次及补充归档。区域请求采用工件平面上的整数毫米。 资料为本地合成样本。

## 源交付

`sources/` 存放 JSON 原件，文件名前两位是到达序号，同一序号内的各表属于同次交付。每个文件有 `intake`、`table`、`records`，记录 `id` 在所属表内唯一。`source-fields.json` 列出各表字段类型，空值用 `null`，空集合用 `[]`。业务时间按下方约定解释。

| 数据表 | 说明 |
| --- | --- |
| `captures` | 相机拍次和完整图像规格。 |
| `geometry` | 按拍次发布的网格空间合同。 |
| `tiles` | 已登记的源小块。行末的 size 和 sha256 由提供方清单给出。 |
| `preview` | 现有读片端的线性灰阶表。 |
| `quality` | 已经签发的作废缘由及作用范围，region 为 x0,y0,x1,y1 的像素区间。 |
| `requests` | 两个使用者提供的取片需求，区域是工件坐标。 |
| `reference_pixels` | 相机供应方独立提供的像素校准点，实际样值为读取坐标标定用途。 |
| `prior_claims` | 已经签发的引用及需要固定的依据。region 为工件坐标。 |

## 来源约定

所有相机图是单通道。p8 为原始 PGM P5，示例头部只有固定的三行，最后一行是最大值 255，紧接着是逐行灰度像素，无行填充。t12 切片按行表示 12 位无符号值，从每个字节的最高位依次向低位排列；每行打包成字节后补零到四字节的整数倍。文件按一个拍次的小块分别交付。每个 tile 在命名的 pixels 范围内，坐标以完整画面的零起始像素边缘为准。以文件的字节长度和 SHA-256 检查小块完整性，校验范围是整块数据。有矛盾的 12 位样本应保留冲突来源，合同明确 replacement 前不能自行选一份。
工件原点 ox,oy 对应画面像素网格的一个角。ux,uy 表示相机像素向右一步在工件上的偏移，vx,vy 表示相机像素向下一步的偏移，单位毫米。取片矩形用左闭右开外框，像素中心落在其中才纳入，掩码按所取画面的行列顺序表示。preview 的 black、white 是固定预览映射的端点，使用线性映射、截断到 0..255 且四舍五入到最近整数，正好一半时向上取整。PGM 是现有查阅端支持的文件格式。quality 的 effect 为 geometry、pixels 或 whole，根据范围使相关取片依据作废，issued_for 指定受影响的采集身份或取向合同。
